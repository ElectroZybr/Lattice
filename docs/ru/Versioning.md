# Версии

Номер версии отвечает на один вопрос: можно ли обновиться, ничего не меняя у себя. Он
считается по совместимости API ([SemVer](https://semver.org/lang/ru/)), а не по объёму работы.

## Номер

| Часть | Когда растёт | Пример |
| --- | --- | --- |
| MAJOR | сломано публичное API: удалено, переименовано, изменена сигнатура или смысл | `1.4.2` → `2.0.0` |
| MINOR | новое API, старый код собирается и работает как раньше | `1.0.1` → `1.1.0` |
| PATCH | только исправления, API не меняется | `1.1.0` → `1.1.1` |

- **Публичное API** — то, что обещано потребителям: `Lattice.hpp`, `Composition.hpp`,
  документированные в `docs/` классы, функции и поведение, публичные заголовки библиотек
  `libs/`. Внутреннее устройство (`detail::`, реестры, `Exports`, `Choices` за пределами
  описанного) меняется свободно и номер не поднимает.
- **Обещание — совместимость исходников, не бинарная.** Раскладка классов меняется и в
  MINOR: пакеты пересобираются вместе с ядром. `soname` библиотек — только MAJOR.
- **Одна версия на всё ядро**: `Lattice` и все библиотеки `libs/` выходят вместе с одним
  номером. `release.yml` проверяет, что `set_version` всех целей совпадает с тегом.

## Ломающие изменения

- **Сначала устаревшее, потом удаление.** Замена появляется в MINOR, старое остаётся с
  `[[deprecated("используй X")]]`; удаляется оно в следующем MAJOR. Десять ломающих правок —
  один MAJOR, а не десять.
- MAJOR выходит редко и с описанием в `CHANGELOG.md`: что менять у себя.

## Между релизами

- `main` — разработка, релиз — тег. Номер не меняется при каждой правке.
- Каждое заметное изменение — строка в разделе «Не выпущено» [CHANGELOG.md](../../CHANGELOG.md)
  с пометкой **сломано**, **добавлено** или **исправлено**, в том же коммите.
- Потребитель берёт `main` без релиза по хешу коммита (рецепты `packages/` клонируют этот
  коммит), а не по ветке: сборка воспроизводима, у каждого коммита своя установка.

## Релиз

1. Номер — по самой сильной пометке раздела «Не выпущено»: есть «сломано» — MAJOR, есть
   «добавлено» — MINOR, иначе PATCH.
2. `set_version` всех целей `xmake.lua` — новый номер; раздел «Не выпущено» становится
   разделом этой версии с датой.
3. Тег `v<номер>` и пуш: `release.yml` проверяет версии, гоняет CI на всех ОС и публикует
   GitHub Release с исходниками.
4. sha256 архива `https://github.com/ElectroZybr/Lattice/archive/refs/tags/v<номер>.tar.gz` —
   в таблицу `versions` файла `packages/sources.lua`.
