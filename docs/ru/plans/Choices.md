# Выбор: фокус, слот и список значений

Одна модель для трёх выборов: значения параметра из списка, кандидата роли Context и
реализации слота. Каждый выбор открыт инструментам параметром (`device gpu`,
`renderer Hardware`, `display wireframe` в CLI; то же в конфигурации и GUI), но правда
живёт у источника: параметр фокуса и слота ничего не хранит — чтение, запись и варианты
идут в Context и в узел слота. Невыбранное не ошибка, пока к нему не обратились;
обращение возвращает сам выбор (`ChoiceRequired`: какой параметр и из чего), и ветка
собирается после него. Основа — [проверка параметров](ParamValidation.md).

| Выбор | Правда | Варианты | В `compose` |
| --- | --- | --- | --- |
| Список значений | поле объекта | `.choices({...})` | список |
| Фокус роли | target scope в Context | видимые кандидаты роли | ничего |
| Слот | реализация узла слота | реализации API из загруженных пакетов | `addSlot<API>(name)` |

Правило неявного выбора одно: при первой нужде единственный вариант выбирается сам и
закрепляется; несколько — нужен явный выбор. Новый вариант (догруженный пакет, новый
кандидат) закреплённый выбор не меняет; уход выбранного кандидата сбрасывает выбор.
Неявный выбор не сохраняется в конфигурацию — только явные записи.

```cpp
// Пакет объявляет реализации статически, в lattice_package.
constinit const Lattice::Implementation implementations[] = {
    Lattice::implementation<Renderer, composeHardware>("Hardware"),
};
extern "C" constinit const Lattice::Package lattice_package{
    .id = "Render", .version = {1, 0, 0}, .implementations = implementations,
};

auto renderer = root.addSlot<Renderer>("renderer");          // пуст до выбора
root.emplace<Viewport>("viewport", renderer.ref());          // ChoiceRequired, если вариантов несколько
```

## Параметр на функциях

- [x] Параметр без поля (`Exports::accessor`): чтение, запись (`ParamResult`) и варианты — функции; правила и отказ как у обычного
- [x] Динамические `choices`: варианты считаются при запросе `rules(id)`; проверку значения делает запись источника
- [x] Параметр, который ядро создаёт само (`Choices`) и снимает вместе с владельцем; наблюдатели видят его как обычный
- [x] Тесты: чтение и запись идут в источник, варианты меняются вместе с ним, отказ на чужом значении

## Фокус

- [x] Параметр выбора роли на узле-владельце scope: у точки фокуса всегда, у scope с двумя кандидатами и больше; локальный перекрывает родительский
- [x] Имя выбора — короткое имя типа с маленькой буквы (`device`), при совпадении — `deviceFocus` (полный ключ роли совпал бы с самой ролью API); имя кандидата — имя экземпляра, при совпадении `Type:name`
- [x] Пустое значение — `reset`
- [x] Неявный выбор при первой нужде закрепляется (`NodeContext::use`); второй кандидат его не меняет; уход кандидата сбрасывает
- [x] Тесты: запись меняет Context и будит `onChange`, локальный выбор, закрепление, сброс при уходе, занятое имя

## Слот

- [x] `Lattice::Implementation { api, name, compose, configure }` в `lattice_package.implementations` (`implementation<API, Compose>(name)`); загрузчик кладёт их в Blueprints как `Пакет::Имя`
- [x] Каталог `Blueprints::implementations(api)`: реализации API из всех загруженных пакетов, включая догруженные во время работы
- [x] `addSlot<API>(name)` — пустой слот; параметр выбора на родителе слота под его именем (ExportId переживает замену), варианты — каталог; одна реализация заполняет слот при первой нужде (`ref()`, конец композиции, `maintain`)
- [x] Запись и `select` — замена: retire → `maintain` → сборка; ответ сразу, пока идёт замена параметр показывает выбранное
- [x] После сборки ядро проверяет, что объект на слоте даёт API
- [x] Старые `slot.choice(name, compose)` и `choice(BlueprintId)` удалены; тесты, пример, Graphics и Shell переведены
- [x] Тесты: каталог, одна реализация заполняет слот в конце композиции, две — пустой слот, выбор и замена из параметра, новая реализация не меняет выбор, отказ на чужом имени

## Ленивое требование выбора

- [x] `ChoiceRequired` (владелец, имя и id параметра, варианты) вместо общей ошибки у `focus.ref()`, `mount`, `require` и `slot.ref()`
- [x] Самая внешняя композиция перехватывает `ChoiceRequired`: узел ветки остаётся пустым и ждёт; выбор внутри ветки — заместитель с относительным именем, его значение — предвыбор настоящего параметра; запись выбора или смена Context — повторная сборка в `maintain`
- [x] `ExportsView::pending()` — выборы, которых ждут отложенные ветки
- [x] Тесты: ветка ждёт слот и внешнюю роль, вложенный выбор по пути, сборка после выбора, предвыбор — явная запись, невостребованное не мешает

## Инструменты (LatticeLab)

- [x] CLI: команда `choices` — ожидаемые выборы с вариантами и id; при запуске — предупреждение ядра с тем же; выбор — `device gpu`, `renderer Hardware`, `#id значение`
- [x] Serializer: выборы сохраняются и загружаются как параметры; выбор для ожидающей ветки — в заместитель, `maintain` собирает ветку, значение сохраняется явным
- [x] Перевод пакетов: камера (Graphics) и окно (Shell) — `addSlot` и `lattice_package.implementations`; интегратор — в плане шага симуляции LatticeLab
