# Выбор: фокус, слот и список значений

Одна модель для трёх выборов: значения параметра из списка, кандидата роли Context и
реализации слота. Каждый выбор открыт инструментам параметром (`device gpu`,
`renderer Hardware`, `display wireframe` в CLI; то же в конфигурации и GUI), но правда
живёт у источника: параметр фокуса и слота ничего не хранит — чтение, запись и варианты
идут в Context и в узел слота. Невыбранное не ошибка, пока к нему не обратились;
обращение возвращает сам выбор (`ChoiceRequired`: какой параметр и из чего), и ветка
собирается после него. Основа — [проверка параметров](ParamValidation.md).

| Выбор | Правда | Варианты | В `compose` |
| --- | --- | --- | --- |
| Список значений | поле объекта | `.choices({...})` | список |
| Фокус роли | target scope в Context | видимые кандидаты роли | ничего |
| Слот | реализация узла слота | реализации API из загруженных пакетов | `addSlot<API>(name)` |

Правило неявного выбора одно: при первой нужде единственный вариант выбирается сам и
закрепляется; несколько — нужен явный выбор. Новый вариант (догруженный пакет, новый
кандидат) закреплённый выбор не меняет; уход выбранного кандидата сбрасывает выбор.
Неявный выбор не сохраняется в конфигурацию — только явные записи.

```cpp
// Пакет объявляет реализации статически, как lattice_package.
extern "C" constinit const Lattice::Implementation lattice_implementations[] = {
    {.api = Lattice::typeKey<Renderer>(), .name = "Hardware", .compose = composeHardware},
};

auto renderer = root.addSlot<Renderer>("renderer");          // пуст до выбора
root.emplace<Viewport>("viewport", renderer.ref());          // ChoiceRequired, если вариантов несколько
```

## Параметр на функциях

- [ ] Параметр без поля: чтение, запись (`ParamResult`) и варианты — функции; правила и отказ как у обычного
- [ ] Динамические `choices`: варианты считаются при запросе `rules(id)` и при проверке записи
- [ ] Параметр, который ядро создаёт и снимает само (не из `compose`); наблюдатели и Serializer видят его как обычный
- [ ] Тесты: чтение и запись идут в источник, варианты меняются вместе с ним, отказ на чужом значении

## Фокус

- [ ] Параметр выбора роли на узле-владельце scope: корень — всегда, ветка — свой, перекрывает родительский
- [ ] Имя выбора — короткое имя типа в нижнем регистре (`device`), при совпадении — полный ключ; имя кандидата — имя экземпляра, при совпадении `Type:name`
- [ ] Запись в ветке без scope создаёт его (как `branch.focus<T>(ref)`); пустое значение — `reset`
- [ ] Неявный выбор при первой нужде закрепляется; второй кандидат его не меняет; уход кандидата сбрасывает
- [ ] Тесты: `device gpu` меняет Context и будит `configure`/`onChange`, локальный выбор, закрепление, сброс при уходе

## Слот

- [ ] `Lattice::Implementation { api, name, compose, configure }` и таблица `lattice_implementations` в пакете; загрузчик кладёт их в каталог Blueprints по API
- [ ] Каталог: реализации API из всех загруженных пакетов, включая догруженные во время работы
- [ ] `addSlot<API>(name)` — пустой слот; параметр выбора на узле слота под его именем, варианты — каталог
- [ ] Запись — замена: retire → `maintain` → сборка; `set` отвечает сразу, пока идёт замена — значение «откуда → куда»
- [ ] После сборки ядро проверяет, что объект на слоте даёт API
- [ ] Старые `slot.choice(name, compose)` и `choice(BlueprintId)` удалить вместе с потребителями
- [ ] Тесты: каталог из нескольких пакетов, единственная реализация закрепляется, две — пустой слот, замена из параметра, догрузка пакета не меняет выбор

## Ленивое требование выбора

- [ ] `ChoiceRequired` (id параметра, варианты) вместо общей ошибки у `focus.ref()`, `require`, `slot.ref()` при неоднозначности
- [ ] `Builder::add` откатывает ветку на `ChoiceRequired` и откладывает её; запись выбора — повторная сборка в `maintain`
- [ ] `ExportsView::pending()` — выборы, которых ждут отложенные ветки
- [ ] Тесты: отложенная ветка собирается после выбора, повторная неоднозначность снова откладывает, невостребованное не мешает

## Инструменты (LatticeLab)

- [ ] CLI: при запуске и по команде — список ожидаемых выборов с вариантами; `device gpu`, `renderer Hardware`
- [ ] Serializer: выборы сохраняются и загружаются как параметры; загрузка выбора собирает отложенные ветки
- [ ] Перевод пакетов: слоты — `addSlot` и `lattice_implementations` (камера, интегратор)
