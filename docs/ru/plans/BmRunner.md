# BmRunner

Измерение асинхронных процессов: фазы, исполнители, реализации одной работы, профиль машины. Проект — [BmRunner](../articles/BmRunner.md).

## Lattice (BmRunner)

- [x] Модель: `Phase` (`Prepare`, `Transfer` In/Out, `Issue`, `Execute`, `Complete`, `Unaccounted`), запись фазы (фаза, метка, источник времени хост/исполнитель, нс, байты)
- [x] `Trace`: спаны хоста (RAII), длительности исполнителя, байты переноса, отложенные отчёты в конце семпла вне замера; функция бенча принимает `Trace&` необязательно
- [x] Capability `Phases`: агрегирует фазы по семплу (медиана на итерацию), `Unaccounted` = стена − Σ, динамическая схема метрик
- [ ] Коэффициент перекрытия Σ фаз / стена (когда появится конвейер с перекрытием)
- [x] Подгонка `fixed + per·x` по любой метрике и по каждой фазе (`affine`, `phases`), неотрицательная
- [ ] Оси параметров: `Batch` рядом с `N`, `Config` с осями
- [x] Тег исполнителя и режим (`Resident` / `Offload`) у бенча; сводная таблица пар `(group, name)` по исполнителям, порог `N*`
- [x] Вывод: разбивка по фазам (столбцы фаз, ГБ/с у переноса, недоступные фазы с причиной)
- [ ] CPU: калибровка уровней памяти (задержка — обход цепочки указателей по рабочим наборам вокруг размеров кешей из SysInfo, пропускная способность — потоковое чтение и запись), один раз на запуск
- [ ] Оценка переноса по уровням из счётчиков (`Cache`, `MemoryTraffic`) × калибровка — источник «оценка модели», в выводе помечен
- [x] Холодный кеш для `Offload` на CPU: вытеснение в `prepare` вне замера
- [ ] Объявленный объём работы (байты чтения и записи, операции на элемент): рабочий набор по оси `N` с границами кешей, кусочная подгонка по уровням, эффективная пропускная способность, арифметическая интенсивность
- [x] Вычитание цены метки спана
- [x] Тесты на синтетическом исполнителе без GPU
- [ ] Документация: из проекта — описание API и пример бенча

## Реализации алгоритма

- [x] Несколько реализаций одной работы, у каждой своя фикстура; `work`/`executor` заменены ими
- [ ] Ось `batch` (K проходов на отправку)
- [x] Результаты и TSV: `implementation`, `params`; ключ строки, слияние, сравнение реализаций (`fixed + per·N`, `N*`)
- [x] `lbm`: имена `работа/вариант/N`; вид «реализации рядом» с `best`; `--sweep`
- [x] Тесты: несколько реализаций с известной ценой, ось, пороги между реализациями

## Открытая регистрация и оси

- [x] `BENCH_WORK(group, work, Input)`: генератор входа (один раз на `N` и оси входа), `check`, `reference`
- [x] `BENCH_IMPLEMENTATION(group, work, name, Fixture)` из любой единицы трансляции: `axis`, `output`, `measure`, фикстура из входа; ошибки регистрации с местами
- [x] Сверка каждого варианта с эталоном на наименьшем `N` до замеров
- [x] `AxisType`, `work.axis<A>()` (вход) и `impl.axis<A>()` (исполнение), `Run` с `n()`, `value<A>()`, `trace()`; строковые `axis(name, values)`, `parameter(name)`, `Threads` удалены
- [x] Набор фаз заново на каждый вариант (`Trace::clear`): фазы `cpu` не попадают в `gpu`
- [x] `--sweep <ось>`, `--axis <ось>=v1,v2`; ошибка набора — сообщение и код 1, а не `terminate`
- [x] TSV: колонки `variant` и `unit`, перевод двух прошлых форматов; `lbm` и BmHistory без правил осей и угадывания единиц
- [x] `Tasks::Workers`, `Tasks::benchPool()` (`Tasks/Workers.hpp`, без зависимости от BmRunner)
- [x] `Boundaries.bench`, `Wgpu.bench` на работах и реализациях, со сверкой GPU против CPU
- [x] Тесты: реализации из двух единиц трансляции, ось входа (перечисление) и ось исполнения, провал сверки, дубль имени, реализация без работы, миграция TSV
- [ ] Фикстура `Reuse` общая для вариантов осей исполнения (сейчас — одна на точку `N` варианта)
- [ ] `lbm`: сводка одной работы из нескольких наборов машины
- [ ] Кластер: `work.partition(n, begin, end, run)`, коммуникатор через `Run` (с `libs/Parallel`)

## Профиль машины

- [ ] `lbm profile`: лучшая реализация работы по диапазонам `N` с порогами — файл в репозитории результатов
- [ ] Чтение профиля пакетом при сборке ветки; приоритет: `lattice.toml` → профиль → `compose`

Бенчи потребителей (`Wgpu.bench`, `Boundaries.bench`, `Graphics.bench`) ведутся в планах LatticeLab (`docs/ru/plans/Benchmarks.md`).

- [x] По умолчанию прогресс, -v текст с прогрессом снизу, -vv прежний текст; прокинуть через lbm.
- [x] Не анимировать перенаправленный вывод; сохранить warnings/errors и TSV.
- [x] Проверить PTY, pipe, узкий терминал, ошибки, CLI lbm и прежние тесты runner.

- [x] Цветная Unicode-полоса и Braille на границах семплов; общий счётчик всех семплов с warmup, итог X/X; проверки PTY и перенаправления.
