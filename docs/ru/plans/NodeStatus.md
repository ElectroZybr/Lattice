# Состояние асинхронных узлов

Цель: у узла, работа которого идёт сама по себе — сервис, устройство, удалённая нода, —
есть состояние живости, которое видят все инструменты одинаково, и даже зависший или упавший
поток показывает себя. Это метаданные узла рядом с lifecycle, а не экспорт объекта: чтение не
идёт через очередь владельца. Потребитель первым — CLI LatticeLab (точка в `tree`/`ls`).

```text
# ориентировочно
Root
├─ Nodes:first
│  ├─ GpuDevice::gpu0 #10      ● lost: device reset
│  └─ Remote::second #15       ● up 16 ms
├─ ClassicMD:Universe1 #20     ● stalled 3 s
└─ CLI #11                     ● up
```

| Цвет (тема) | Состояние |
| --- | --- |
| зелёный | работает, свежее |
| голубой | подключается, перегружен, давно не обновлялся (`stalled`) |
| красный | потерян, упал (`lost`, `failed`) |
| серый | ушёл штатно (`left`), нет на связи (`offline`) |

## Этапы

- [x] **Метаданные статуса узла** — состояние, короткая причина, время последнего обновления, необязательная задержка; запись атомарная, без очереди владельца; чтение через `StatusView`, отдельно от структуры дерева в `TreeView`
  ```cpp
  struct Device { Lattice::Status status; };      // обычный класс, заголовочный контракт
  device.status(device->status);                  // узел показывает статус объекта
  device->status.set(Lattice::Status::State::Lost, "device reset");
  device->status.touch(std::chrono::microseconds{16000});   // свежесть и задержка
  ```
  - [x] Состояния и их смысл, время обновления считает ядро по `touch` (2026-10-30)
  - [x] Ручка статуса в `ObjectBuild`; узел без ручки статуса не показывает (2026-10-30)
  - [x] Подписка на смену состояния — для лога и реакций, вызывается в `maintain` (2026-10-30)
- [x] **Статус сервисов ведёт ядро** — `run` вышел с исключением → `failed` с текстом; обороты цикла (`idle`/`maintain`) перестали расти дольше порога → `stalled`; после `stop` → `left`
  - [x] Метка `[service]` в дереве уходит: сервис показан точкой статуса (2026-10-30)
  - [x] Дампы дерева и Context из ядра убраны: дерево показывает CLI, отчёт об аварии — текст исключения (2026-10-30)
- [x] **Тесты** — запись статуса из чужого потока без гонок; `stalled` у зависшего сервиса; `failed` у сервиса с исключением; подписка вызывается один раз на смену
