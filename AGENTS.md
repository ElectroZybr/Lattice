## Обязательно

- Экономь токены и вызовы инструментов: проверки сборки и поведения выполняй в конце работы,
  по затронутым изменениям. Промежуточные проверки — только для устранения конкретной ошибки
  или неопределённости; успешные проверки без новых оснований не повторяй.
- Ядро — маленькие ортогональные примитивы; предметное поведение — у потребителей. Новый
  механизм — только с реальным сценарием.
- Не держи `Node&`/`Node*` через вызов пользовательского кода: сохрани `NodeId`, получи заново.
- Не открывай пакетам `NodeRegistry`, `NodeFactory`, `Builder` и другие внутренности.
- Контракты для обычных классов — заголовочные, без линковки runtime.
- Выбор никогда не молча: неоднозначность — ошибка со списком кандидатов.
- Новая возможность — тест в `tests/` (ядро) или `libs/<имя>/tests/` (библиотека) и раздел с
  примером в `Composition.md`.
- Сборка всегда с `-y`; потребители после правки ядра — `xmake require -f -y lattice`.
- Планы ведутся в `docs/ru/plans/`; выполненное отмечается там.
